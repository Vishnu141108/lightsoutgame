# Lights Out Puzzle

A complete, polished desktop implementation of the classic **5 × 5 Lights Out**
puzzle, written in Python with Pygame. Every board is solvable, every
difficulty is verified with a GF(2) solver, and all artwork, UI, animation and
sound effects are generated by the game itself.

## Features

- **Complete screen flow**: Main Menu → Difficulty → Gameplay → Victory /
  Defeat, plus Settings → Themes / Sound / Volume and a scrollable
  Instructions guide.
- **One window only** — a central screen manager builds, relayouts and
  crossfades every screen inside the same resizable window.
- **Three light themes** — Square (default), Circle and Light Bulb. The Square
  theme is a clean white-on-black chessboard (white ON, black OFF); Circle and
  Light Bulb keep the original yellow-on/dark-off palette. Selection is
  immediate and previewed on each theme card.
- **Sound, victory music and voice-over** — generated click, button, toggle,
  undo, volume, victory and defeat effects. The victory screen can play the
  custom `assets/audio/victory_music.mp3` track and speak “You have won the
  game!” using an offline, cached voice clip. Both respect the Sound switch and
  master volume.
- **Volume 0–10** — ten visual bars, +/− buttons, keyboard control, instant
  application to every effect, the victory music and the voice-over.
- **Clean vector icons and balanced gameplay header** — redrawn undo/restart
  curved arrows, a house-shaped Home button and an equal-gap difficulty /
  theme / Home header.
- **Verified puzzle generation** — boards are produced from random press
  patterns and then checked by a Gaussian-elimination solver over GF(2).
  Difficulty is based on the **computed minimum number of presses**, never on
  how many random clicks were used to scramble the board.
- **Timer starts on the first valid move**, displayed as `MM:SS`, with a
  colour-changing progress bar and an automatic defeat when it expires.
- **Undo, Restart and New Puzzle** — Undo restores the board, move count and
  timer snapshot (undoing the first move returns the clock to its not-started
  state). Restart restores the original board. New Puzzle deals a fresh board
  at the same difficulty.
- **Victory and defeat presentations** — animated medallion, confetti, stats,
  and Play Again / Try Again / New Puzzle / Main Menu actions.
- **Resizable layout** — designed for 1100 × 750, works down to 900 × 620 and
  up to large desktop windows through a single UI scale factor.
- **No blocking waits** — the game loop uses `clock.tick(60)`; there is no
  `time.sleep()` anywhere in the game.

## Requirements

- Python **3.10 or newer**
- `pygame-ce` **2.5.0 or newer** (a drop-in, actively maintained fork of
  Pygame; imported as `pygame`)
- Windows, macOS or Linux. Windows is the primary target: the UI uses Segoe UI
  when available, with automatic fallbacks elsewhere, and the optional
  voice-over uses the built-in Windows speech engine.

No other packages are required. The game does not download anything at run
time. Sound effects are synthesised in memory; the only bundled audio assets
are the optional victory music and cached voice-over, and both are handled
gracefully if missing.

## Install and run

From the project folder:

```powershell
python -m pip install -r requirements.txt
python main.py
```

If `python` is not on your PATH, use the launcher that matches your install,
for example `py -3 main.py`.

To run the automated checks:

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
python tests\smoke_test.py
```

The smoke test forces SDL's dummy video/audio drivers, so it opens no window
and needs no speakers. It writes fresh screenshots to `tests/screenshots/`.

## How to play

Click a light. That light and its orthogonal neighbours — **up, down, left and
right** — flip between ON and OFF. Diagonal neighbours never change. Corners
therefore affect three lights, edges affect four, and interior lights affect
five.

Turn **every** light off before the timer reaches zero. The timer starts on
your first valid move.

- **Undo** reverses the last move and restores the clock to that moment.
- **Restart** returns the board to its original pattern and clears the timer.
- **New Puzzle** generates a fresh verified board at the same difficulty.

The move counter shows how many presses you have made; `MIN n` shows the
shortest possible solution for the current board.

## Difficulty design — and why HARD is 13–15

| Difficulty | Minimum presses | Time limit | Colour |
| --- | --- | --- | --- |
| Easy | **1–4** | 05:00 | Green |
| Medium | **5–12** | 10:00 | Orange |
| Hard | **13–15** | 15:00 | Red |

The brief asked for Medium at 5–15 presses and Hard at 16–25. One of those
ranges cannot exist, and the game deliberately does not fake it.

For the standard 5 × 5 Lights Out matrix, the 25 × 25 toggle matrix has rank
**23**, so its null space has dimension **2**. The three non-zero “quiet”
press patterns have weights 16, 12 and 12, and every solvable board has four
equivalent press patterns (a solution plus those quiet patterns). The game
ships with `tests/verify_ceiling.py`, which enumerates **all 8,388,608**
distinct solvable boards with a Gray code. It proves the largest possible
**minimum** solution is **15 presses** (witness board `0xF8EE3E`). A board
whose shortest solution needed 16–25 presses simply does not exist. Producing
one would require changing the rules (for example wrapping edges or using a
larger grid), which would no longer be classic Lights Out.

The verified distribution of optimal lengths is:

| Minimum presses | Boards | Share |
| ---: | ---: | ---: |
| 0 | 1 | — |
| 1 | 25 | — |
| 2 | 300 | — |
| 3 | 2,300 | — |
| 4 | 12,650 | 0.15 % |
| 5 | 53,130 | 0.63 % |
| 6 | 176,176 | 2.10 % |
| 7 | 467,104 | 5.57 % |
| 8 | 982,335 | 11.71 % |
| 9 | 1,596,279 | 19.03 % |
| 10 | 1,935,294 | 23.07 % |
| 11 | 1,684,446 | 20.08 % |
| 12 | 1,004,934 | 11.98 % |
| 13 | 383,670 | 4.57 % |
| 14 | 82,614 | 0.98 % |
| 15 | 7,350 | 0.088 % |

The game therefore uses the genuinely hardest boards that exist for HARD:
**13–15 minimum presses**. MEDIUM was tightened to 5–12 so the three tiers
remain distinct and ordered. These decisions are documented in
`lights_out/config.py` next to the difficulty table.

Every generated board is checked by the solver:

1. Build a random press pattern of a tier-appropriate weight.
2. Apply it to an all-off board to obtain a guaranteed-solvable board.
3. Solve that board with Gaussian elimination over GF(2).
4. Keep it only if the computed minimum falls inside the tier.
5. If the attempt budget is exhausted, use one of three pre-verified fallback
   boards (and their eight rotations/reflections), so generation cannot loop
   forever or fail.

Generation is fast: measured on the development machine (Python 3.14.7,
pygame-ce 2.5.8), 100 boards per tier averaged **0.08 ms** (Easy), **0.09 ms**
(Medium) and **0.93 ms** (Hard), with a 6.94 ms worst case.

## How the code works

### Application shell — `main.py`

`Game` owns exactly one Pygame display (`1100 × 750`, `RESIZABLE`, title
`Lights Out Puzzle`, custom window icon) and one shared set of objects:

- `settings: GameSettings` — theme, sound flag and volume.
- `audio: SoundManager` — lazy, device-safe audio.
- `generator: PuzzleGenerator` — session history plus the solver.
- `background: Background` — cached gradient, light pools and dot grid.
- `screen: Screen` — the currently active screen.

`Game.show(name, **kwargs)` is the only navigation entry point. It:

1. copies the current display for the crossfade,
2. calls the old screen’s `on_leave()`,
3. constructs the new screen (arguments such as `puzzle=` or `result=` are
   passed through),
4. calls `relayout(width, height)` followed by `on_enter()`,
5. starts a 0.28 s fade and a very short input lock so the click that won a
   game cannot also press a result-screen button.

Every screen subclasses `Screen`, which stores the current size, the shared UI
scale and the mouse position. `relayout()` updates the scale and calls the
screen’s `build_layout()`, which recreates all widget rectangles. Because every
screen can rebuild its layout, resizing never leaves stale hit boxes.

The loop processes one `pygame.event` queue, ignores input during the short
lock, syncs any window resize, updates the screen and audio, draws the cached
background, then the screen, then the fade snapshot, and finally flips the
display. `clock.tick(60)` caps the frame rate and provides `dt`; nothing calls
`time.sleep()`.

### Puzzle rules and solver — `lights_out/puzzle.py`

Boards are 25-bit integers: bit `row * 5 + col` is 1 when the light is ON.
`TOGGLE_MASKS` pre-computes the cross mask for every cell, and both the player
and the generator go through the same `toggle_cell()` function.

The solver builds the 25-row augmented matrix over GF(2):

- equation *i* says the XOR of presses affecting cell *i* must equal cell *i*’s
  current state,
- Gaussian elimination produces reduced row-echelon form,
- an inconsistent row means the board is unsolvable,
- the two free variables give the two-dimensional null space,
- all four solutions are enumerated and the one with the fewest presses is
  chosen.

`minimum_solution(board)` returns `(press_count, press_pattern)` or `None`.
`PuzzleGenerator.generate()` rejects boards outside the requested verified
range and falls back to checked constants if its attempt budget runs out.
`Puzzle.is_valid()` re-checks a board on demand.

The module imports no Pygame, so it can be tested and reasoned about in
isolation.

### Theme rendering — `lights_out/cells.py`

Each theme has its own renderer while sharing the same logical ON/OFF state
and smooth press transition.

- **Square** — a black-and-white chessboard: white ON cells, black OFF cells
  with a subtle outline so every square stays visible.
- **Circle** — soft yellow-on / dark-off glowing orbs with a clean outline.
- **Light Bulb** — a rounded glass, narrower neck and small base; bright yellow
  with a glow when ON, dark grey with a visible outline when OFF.

`draw_cell()` blends between the ON and OFF look using an animation value, so
presses fade smoothly instead of snapping. Theme previews reuse the same
renderer, which guarantees that the preview matches gameplay.

### UI toolkit — `lights_out/ui.py`, `widgets.py`

`ui.py` owns font discovery (Segoe UI / Segoe UI Semibold / Bahnschrift on
Windows, with cross-platform fallbacks), cached text surfaces, word wrapping,
radial glows, rounded panels, a scrollbar and about twenty vector icons drawn
with `pygame.draw` primitives. Undo and Restart use mirrored, smoothly
anti-aliased curved arrows; Home uses a roof, body and door. `widgets.py`
builds the interactive pieces: animated buttons with hover/press states, a
sliding toggle, settings rows, theme cards, difficulty cards, confetti and
ambient dust.

No image files are needed; the entire interface is vector-drawn at runtime.

### Timer and undo — `lights_out/timer.py`

`GameTimer` is driven by `pygame.time.get_ticks()`. It stores accumulated time
and the timestamp when the current run began, so `elapsed_ms()`,
`remaining_ms()` and `is_expired()` are cheap and non-blocking. A
`TimerSnapshot` captures remaining time plus started/running flags. Undo
restores that snapshot: undoing the first move therefore returns to the
“not started” state with the full allowance, exactly as required.

### Gameplay — `lights_out/screens/gameplay.py`

The screen keeps the puzzle, the current board, the original board, the move
count, the timer and an undo stack of `(board, moves, timer snapshot)` tuples.
A press on a cell:

1. pushes an undo state,
2. starts the timer if it has not started,
3. XORs the cell’s cross,
4. increments the move counter,
5. triggers pulse/hover animations,
6. checks for an all-off board and moves to Victory.

Timeout is polled in `update()` rather than in an event handler, so it fires
even if the user is not clicking. After either result the gameplay screen is
replaced; its move/undo/restart actions are also guarded by a `finished` flag.

### Results — `lights_out/screens/results.py`

Victory builds a `GameResult` with difficulty, theme, moves, elapsed time,
time limit, original board and verified minimum. It plays the victory chord,
the cached voice-over and — when sound is on — the custom streamed victory
music, animates a bobbing trophy with rotating rays, and rains confetti. The
music starts only on entering the Victory screen and stops on Play Again, Main
Menu, Escape or app shutdown. Play Again generates a fresh board at the same
difficulty and falls back to the difficulty picker if generation ever fails.

Defeat plays the defeat cadence and shows the clock medallion with difficulty,
moves played and the time limit. Try Again reconstructs the *same* board via
`minimum_solution(original_board)`; New Puzzle generates a fresh board at the
same difficulty.

## Audio

`SoundManager` synthesises all seven effects into in-memory mono WAVs with
Python’s `wave` and `struct` modules, then loads them with
`pygame.mixer.Sound`. Each effect has a trim level; the master volume is
applied per channel. If mixer initialisation fails (headless server, no audio
device, broken driver), `available` becomes `False` and every play call is a
safe no-op — the game remains fully playable.

Sound is ON and volume 7 by default. The Sound screen can mute everything
(including a pending voice-over and victory music); the Volume screen changes
the master level live. All audio calls catch `pygame.error`.

The optional victory track lives at `assets/audio/victory_music.mp3`. It is
streamed with `pygame.mixer.music` and loops only while the Victory screen is
open. Missing files, unsupported codecs and mixer failures are ignored so the
existing victory chord and voice-over still work.

The optional voice clip lives at `assets/generated/victory_voice.wav`. If it
is missing on Windows, a background thread generates it once with
`System.Speech.Synthesis` (SAPI) and the game picks it up through
`SoundManager.update()`. This never blocks the loop and never crashes if the
speech engine, PowerShell or the file is unavailable.

## Troubleshooting

**`ModuleNotFoundError: No module named 'pygame'`**
Run `python -m pip install -r requirements.txt` with the same interpreter you
use to launch the game. `pygame-ce` provides the `pygame` module.

**No sound / mixer warning**
The game still works. Check that the system output device is available, or
raise the volume on the Volume screen. Muting is mirrored in Settings.

**The game window is too small to read**
Resize it; everything relayouts from the current window size. The design size
is 1100 × 750 and the enforced minimum is 900 × 620.

**The voice-over is missing**
It is optional. On Windows, delete `assets/generated/victory_voice.wav` and
start the game once to regenerate it. On other systems the victory chord still
plays; no speech engine is required.

**Custom fonts differ on macOS/Linux**
The UI automatically falls back to DejaVu Sans / Liberation Sans, so layout and
all functionality remain intact.
